01 Problem Statement

Academic credential fraud is endemic across Africa and is actively distorting hiring markets, professional licensing, and institutional admissions. Forged WAEC results, purchased university degrees, and fabricated NYSC discharge letters circulate freely — some indistinguishable from genuine documents to the naked eye.

30%
Of CVs submitted in Nigerian hiring contain at least one unverifiable credential
72hrs
Average manual verification turnaround from WAEC or JAMB — if completed at all
₦15B+
Estimated annual value of fraudulent credentials circulating in West Africa
The Verification Gap

Most employers accept photocopies or PDF scans, with no mechanism to confirm authenticity against issuing institutions. WAEC and NECO do offer online verification portals — but they require manual lookups per candidate, have no API, are frequently slow or unavailable, and are rarely used systematically in hiring pipelines.

Why It Cascades

A fraudulent medical degree leads to an unqualified doctor practicing. A forged engineering certificate leads to unsafe infrastructure. A fake NYSC letter means someone bypassed national service. Credential fraud is not a white-collar inconvenience — it has downstream physical harm. The consequences are most severe in regulated professions where competence is assumed based on certification.

02 Solution Overview

CertChain AI is a multi-modal credential intelligence platform that accepts a scanned or photographed academic document, runs it through a four-layer AI pipeline, and returns an interpretable Authenticity Score (0–100) along with structured entity extraction and an institutional cross-check result.

Employers, HR platforms, and licensing bodies integrate CertChain via API. The Squad API integration gates credential-dependent transactions — for example, a professional licensing fee payment, a job offer letter release, or a university admission fee disbursement — until the candidate's credentials clear a configurable authenticity threshold.

→

The key architectural insight: CertChain does not replace institutional verification. It pre-screens at scale so that the expensive, manual institutional check is only triggered for the small percentage of documents that pass AI pre-screening but warrant human confirmation — inverting the current workflow where everything waits in a manual queue.

05 AI / ML Core Engine

5.1 — Document Classification & Type Detection

A ResNet-50 fine-tuned classifier first identifies the document type from the uploaded image — WAEC result checker, NECO certificate, university degree scroll, HND transcript, NYSC discharge letter, professional cert, or unknown. Type classification determines which downstream model pipeline and schema to apply. An unknown or ambiguous document type automatically triggers a human review flag regardless of other scores.

5.2 — Forgery Detection (Computer Vision)

This is the technical centrepiece. A twin-branch CNN (EfficientNet-B4 backbone) is trained on pairs of genuine and manipulated certificate images. The model detects:

Font inconsistencies (character spacing, weight mismatch across lines) · Image splicing artefacts detected via Error Level Analysis (ELA) · Missing or degraded security features (watermarks, embossed seals, holographic strips) · Pixel-level tampering signatures in grade fields and name blocks · Inconsistent JPEG compression levels suggesting localised editing

Training data is built from: genuine documents collected with institutional consent, synthetically generated tampered versions using known forgery techniques (Photoshop, online certificate generators), and augmented with noise, scan distortions, and lighting variation to ensure robustness to real-world scan quality.

5.3 — Entity Extraction & Semantic Validation (NLP)

A LayoutLM v3 model — designed specifically for visually rich documents — extracts structured entities: candidate name, exam number, year, institution, subject grades, and awarding body. These are cross-validated against a curated schema database of known valid institution names, course codes, grading systems, and date ranges.

A BERT-based anomaly classifier then checks for semantic impossibilities: a degree dated before the institution was accredited, a grade of A1 in a subject WAEC discontinued in that year, a university transcript citing a course combination that doesn't exist in any Nigerian curriculum, or an institution name that is a slight variant of a real one (a common cheap forgery signal).

5.4 — Institutional Registry Cross-Check

For documents from institutions with available APIs or queryable registries — WAEC online verification, NYSC verification portal, JAMB CAPS — CertChain performs a live lookup using the extracted exam number or registration number. For institutions without live APIs, CertChain queries its own institutional pattern database (document format signatures, certificate number ranges, stamp designs per institution per year) built from verified historical samples.

5.5 — Anomaly Network Detection

A lightweight graph anomaly model detects coordinated forgery rings: if 15 candidates from the same employer submission share suspiciously similar document templates, serial number formats, or extraction fingerprints, the entire batch is flagged for elevated review — even if individual documents score acceptably on their own.

07 Squad API Integration

Integration Strategy — Credential-Gated Transactions

Squad API connects CertChain to the real-world financial consequences of credential fraud. Rather than merely flagging a forged document and sending an email, CertChain makes the credential outcome economically enforceable — no payment moves until the document clears.

Core Integration Flows

01

Professional Licensing Fee Gate

A medical council collects licensing fees via Squad. CertChain issues a credential_token only after the applicant's MBBS degree passes the authenticity threshold. The Squad payment link is conditionally activated — before the token is issued, the payment page shows "Credential verification pending."

02

University Admission Deposit Hold

Applicant pays admission deposit via Squad into a held escrow state. CertChain verifies the submitted WAEC/JAMB results. On passing, POST /v1/disbursement/release moves the deposit to the institution's settlement account. On failure, POST /v1/transaction/reversal refunds the candidate.

03

Employer Pre-Employment Payment Hold

Background check firms charge employers per verified candidate. CertChain completes verification, then triggers a conditional Squad payout to the employer's API integration partner. Failed verifications generate a rejection webhook with the specific anomaly flags returned to the employer system.

04

Audit Webhook Receipts

Every Squad transaction event — initiated, held, released, reversed — is written to CertChain's immutable audit ledger with the associated document_id, authenticity_score, and reviewer action. Creates a tamper-proof chain from document submission to financial outcome.

08 Authenticity Score Design

Each document receives a composite Authenticity Score (0–100) from a weighted ensemble of five signal groups:

Visual Forgery Detection (CNN)
35%
Security Feature Integrity
20%
Semantic Entity Validation
20%
Registry Cross-Check
15%
Batch Anomaly Signal
10%

Score bands:  85–100 Verified — auto-pass  55–84 Inconclusive — human review  0–54 High-risk — reject / hold

Registry cross-check weight increases to 40% if a live WAEC/JAMB lookup succeeds — in that case the registry result dominates and all other signals are secondary. This reflects that a confirmed institutional match is the ground truth no AI model can supersede.
